# Q2Route M4: DNS through the proxy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plaintext DNS is routed by the name being asked: names whose group is Direct (e.g. `*.ir`) resolve directly as today; names that would be proxied are resolved through the proxy, so the ISP never sees them; DoH/DoT endpoints are blocked for proxied apps so browsers fall back to DNS Q2Route controls; DNS answers feed an IP → names map that lets domain rules decide without waiting for an SNI peek.

**Architecture:** Port 53 stops being blanket always-Direct. UDP/53 queries are parsed in the packet loop: Direct → passed unchanged to the original server; Block → a REFUSED reply is injected; Proxy → a `DnsProxy` sends the query over a shared SOCKS5 UDP association to the configured proxy resolver (default `1.1.1.1:53`) and injects the answer back as if it came from the original server. If the proxy can't carry UDP, an IPv4 query gets a truncated (TC=1) reply so the client retries over TCP, and TCP/53 is redirected into the existing TCP relay, which reads the DNS-over-TCP query, decides by name and tunnels Proxy names with CONNECT to the resolver. A sniff-only WinDivert handle reads inbound DNS answers into a `DomainMap`.

**Tech Stack:** Rust, tokio, WinDivert (existing), SOCKS5 UDP (M3).

**Spec:** `docs/specs/2026-11-05-q2route-design.md` — §3 "No DNS leaks for names that resolve to proxied destinations", §5.4 (DNS-answer mapping), §5.5 (DNS), §5.8 (DNS routed by queried name only; IP mapping to several groups → peek, else most protective Proxy > Block > Direct).

**Scope split (builder's call):** spec step 3 is split into M4 (this plan: DNS), M5 (kill switch, persistent WFP) and M6 (IPv6 relay). Each gets its own plan.

## Global Constraints

- **Fail closed:** a DNS query for a name that routes to Proxy is never sent to its original server. Every failure answers REFUSED, TC=1 (IPv4 only) or drops — never passes.
- **DNS is decided by the queried name only** (spec §5.8): the requesting app is ignored (most queries come from the DNS Client service). Rules that have app conditions are skipped for DNS; rules with domain conditions apply; a name matching no domain rule follows the catch-all group's action.
- The Windows DNS cache is flushed on start and stop (already done) and when DNS settings change.
- IPv6 in M4: UDP/53 over IPv6 is handled (Direct pass / Block REFUSED / Proxy through the association with an injected IPv6 reply); when the association is unavailable an IPv6 query gets REFUSED (not TC). **TCP/53 over IPv6 stays always-Direct in M4** (no IPv6 TCP relay until M6) — documented gap.
- NTP (UDP 123), LAN/loopback/multicast destinations stay always-Direct exactly as today. DNS to a LAN resolver (e.g. the router `192.168.1.1`) is still routed by name: LAN *destinations* are always-Direct for other ports, but port 53 is now decided by name regardless of the server address (otherwise the router would forward proxied names to the ISP).
- Config: `settings.dns = { proxy_resolver: "1.1.1.1:53", block_doh: true }`, both `#[serde(default)]`; existing configs load unchanged.
- IPC: new requests appended at the end of `Request`.
- `cargo clippy --workspace --all-targets` clean, `cargo fmt --all`, all tests pass; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisions made in this plan (builder's calls)

- **One shared association per profile** for proxied DNS (not per app socket): queries get a fresh 16-bit id on the way out (remapped back on the way in), 5 s timeout, at most 1024 in flight per profile (more → REFUSED).
- **Proxy resolver**: one address for all proxied names, default `1.1.1.1:53`, configurable on the DNS page.
- **DoH/DoT blocking** (`block_doh`, default on): for flows whose route is Proxy, TCP/UDP port 853 is Blocked, and TCP 443 whose domain (SNI or mapped name) is on a built-in list is Blocked: `dns.google`, `dns.google.com`, `cloudflare-dns.com`, `mozilla.cloudflare-dns.com`, `chrome.cloudflare-dns.com`, `one.one.one.one`, `1dot1dot1dot1.cloudflare-dns.com`, `dns.quad9.net`, `dns9.quad9.net`, `doh.opendns.com`, `dns.adguard-dns.com`, `doh.cleanbrowsing.org`, `dns.nextdns.io`. Direct apps are unaffected.
- **DomainMap**: up to 65 536 IPs, up to 8 names per IP, entry lifetime = answer TTL clamped to [60 s, 3600 s]; CNAME chains map the final A/AAAA addresses to the *queried* name.
- **Several names for one IP** (spec §5.8): TCP 80/443 → peek (`NeedDomain`); otherwise the most protective route among the names' decisions wins (Proxy > Block > Direct).
- **Block for a DNS name** → REFUSED (UDP) / connection closed (TCP).

## Review Focus

1. A proxied name asked over UDP while v2ray's UDP is off: the client gets TC=1, retries over TCP/53, and resolves through the proxy with CONNECT; nothing reaches the ISP resolver. Test: `udp_unavailable_answers_tc_then_tcp_resolves_via_proxy` (Task 4).
2. The router as resolver (`192.168.1.1:53`) asked for a proxied name: routed by name (through the proxy), not passed because the server is on the LAN. Test: `lan_resolver_still_routed_by_name` (Task 1).
3. A reply whose id doesn't match any pending query, or arrives after the 5 s timeout, is dropped (no wrong answer delivered to an app). Test: `unknown_or_late_reply_dropped` (Task 3).
4. A CDN IP that maps to an `.ir` name and a proxied name: a non-HTTP TCP connection to it goes through the proxy (most protective), an HTTPS one is peeked. Test: `mapped_conflict_most_protective_or_peek` (Task 2).
5. Malformed DNS (truncated header, compressed-name loop, zero questions) never panics; a malformed UDP/53 query can't be routed by name, so it is **dropped** unless the catch-all action is Direct (then passed). Test: `malformed_query_dropped_when_catch_all_proxied` (Task 3).

                        pub msg: Vec<u8>, pub addr: Address }
  pub struct DnsProxy { .. }
  impl DnsProxy {

Association unavailable (non-SOCKS5 profile, failure, in backoff, `max_inflight` reached): IPv4 → inject `truncated(query)`; IPv6 → inject `refused(query)`. One `debug!` line per query (`dns name=.. type=.. via=direct|proxy '<id>'|block`), not info (DNS is chatty). TCP/53 keeps the Task 1 pass-through guard until Task 4.

**Interfaces / behaviour:**
- IPv4 TCP to port 53 becomes a normal non-Direct-until-known flow: `decide` returns `NeedDomain`-like handling — simplest: the packet loop treats every IPv4 TCP/53 SYN (not own pid / proxy endpoint) as redirect-to-relay (`NewRedirect`), and the relay's `handle` branches on `orig.dst.port() == 53`.
- Relay DNS branch: read the 2-byte length + message (max 4096 bytes, 5 s); `parse_query` fails → close. `decide_dns`: Direct → TCP connect to the original destination directly (own socket, excluded like other direct upstreams) and write the length+message, then pump both ways; Block → close; Proxy → `connect_via(profile, Target::Ip(proxy_resolver), PROXY_TIMEOUT)`, write, pump. Every answer read back on the Proxy path that parses is fed to `ctx.domains` (parse each length-prefixed message as it passes; don't buffer the stream). Proxy failure → close (no direct fallback), ProxyDown/Up as for other relayed flows. ConnLog row: domain = queried name, route as decided.
- IPv6 TCP/53: unchanged always-Direct (documented M4 gap; keep a passing test that pins it so M6 notices).
