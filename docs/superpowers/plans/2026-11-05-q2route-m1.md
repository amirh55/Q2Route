# Q2Route Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working first version of Q2Route that you can use every day:
- A Windows service captures all TCP with WinDivert.
- It routes each connection Direct, Proxy (SOCKS5 or HTTP) or Block, using ordered groups. Groups match by app (with child processes), by domain (`*.ir`, read from SNI/Host) and by IP or port.
- It fails closed: proxied traffic is never sent direct.
- An egui UI provides dashboard group toggles, proxy profiles and a tray icon with live traffic bars.

**Architecture:**
- A Cargo workspace with three crates.
- `q2route-core` holds the pure, platform-neutral, fully unit-tested logic: config, matchers, the decision engine, SNI parsing, proxy clients and IPC framing.
- `q2route-service` is the Windows-only engine: WinDivert FFI, flow and PID tracking, TCP NAT redirect to a local transparent relay, the named-pipe IPC server and the Windows service wrapper.
- `q2route` is the UI: eframe plus a tray icon, and an IPC client.

**Tech Stack:** Rust stable (MSVC), tokio, serde, toml, serde_json, thiserror, tracing, arc-swap, dashmap, tokio-util (CancellationToken), ipnet, globset, etherparse, windows (Win32 APIs), windows-service, eframe/egui, tray-icon, WinDivert 2.2.2.

**Spec:** `docs/specs/2026-11-05-q2route-design.md`

**Scope:** This plan covers Milestone 1 only. It deliberately leaves the following for later plans, which reuse this one's interfaces:
- UDP relay
- DNS relay and the IP→domain map
- geosite/geoip
- The WFP kill switch
- The Connections view, data usage, log and settings tabs
- DPAPI-protected passwords
- The installer

**While M1 is in place, UDP and IPv6 from any flow routed to Proxy are blocked, not sent direct.** That keeps the anti-goal intact until M2.

## Global Constraints

- Windows 10/11 x64 only. Rust stable with the MSVC toolchain.
- UI copy is in English.
- Config file: `%ProgramData%\Q2Route\config.toml`. Logs: `%ProgramData%\Q2Route\logs`.
- Named pipe: `\\.\pipe\q2route`. The ACL grants access to Interactive Users and Administrators.
- **No fail-open.** If a flow is routed to Proxy and the proxy connection fails, the flow is closed or blocked, never sent direct.
- **Deliberate Stop**: everything goes direct. The service closes the proxied connections it relays and flushes the DNS cache. The status reads "Stopped: all traffic direct".
- Loopback and private or LAN destinations (`127.0.0.0/8`, `::1`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `fe80::/10`) always go Direct.
- **The always-direct process list** is prefilled with `v2ray.exe`, `xray.exe`, `sing-box.exe`, `v2rayN.exe`, `nekoray.exe`, `hiddify.exe` and `clash*.exe`. In addition, the process that listens on each configured proxy's port is always Direct.
- **An app's own match beats an inherited match**, whatever the group order.
- **Seed groups on first run, in this order:**
  1. "Iranian sites" (`*.ir`, Direct, enabled)
  2. "Steam" (`steam.exe` plus its children, Direct, **disabled**)
  3. "Games" (empty, Direct, enabled)
  4. "Everything else" (catch-all, Proxy `v2ray`, enabled)
- **Seed proxy:** id `v2ray`, SOCKS5 at `127.0.0.1:10808`, no authentication.
- WinDivert 2.2.2 (`WinDivert.dll` and `WinDivert64.sys`) is downloaded from the official GitHub releases into `vendor/windivert/` and copied next to the built executables.

## Review Focus

1. **Proxy (v2ray) down or refusing a connection.** A flow routed to Proxy is closed and never connected direct. A `ProxyDown` event is sent to the UI. Tested in Task 12.
2. **v2ray itself, and the relay's own direct upstream sockets.** They must never be captured, or the result is a routing loop. Tested in Tasks 6 and 12.
3. **Child processes.**
   - A process started after the service, whose parent is `steam.exe`, inherits Steam's route.
   - A game launched by Steam that has its own rule in a lower group takes its own rule.
   - Tested in Task 6.
4. **Domain edge cases.**
   - `*.ir` matches `digikala.ir`, `www.digikala.ir` and `ir`.
   - `*.ir` does not match `notir.com` or `ir.com`.
   - Matching is case-insensitive and ignores a trailing dot.
   - A server-first protocol, which sends no client bytes within 300 ms, is decided without a domain.
   - Tested in Tasks 3, 6 and 7.
5. **Toggle persistence and UI loss.**
   - A toggle from the dashboard or tray survives a service restart.
   - Closing or killing the UI does not change routing.
   - Tested in Tasks 2, 13 and 15.

### Task 6: Decision engine (core)

**Files:**
- Create: `crates/q2route-core/src/decide.rs`
- Test: `crates/q2route-core/tests/decide.rs`

**Interfaces:**
- Consumes: `RuleSet` (Task 5), `ProcessTree` (Task 4).
- Produces:
  ```rust
  pub struct FlowInfo<'a> { pub proto: Protocol, pub pid: u32, pub dst: SocketAddr, pub domain: Option<&'a str> }
  pub enum Route { Direct, Block, Proxy(ProfileId) }
  pub enum MatchReason { AlwaysDirectDst, AlwaysDirectApp, ExcludedPid, Own, Inherited { from_pid: u32 }, CatchAll, NoMatch }
  pub struct MatchInfo { pub group_id: Option<GroupId>, pub reason: MatchReason }
  pub enum Decision { Final(Route, MatchInfo), NeedDomain }
  pub fn decide(rs:&RuleSet, tree:&ProcessTree, excluded_pids:&HashSet<u32>, f:&FlowInfo) -> Decision
  ```

**Algorithm.** The tests pin this down, so implement exactly this order:

1. If `is_always_direct_dst(dst)` → `Direct` / `AlwaysDirectDst`.
2. If the pid is in `excluded_pids` → `Direct` / `ExcludedPid`.
3. If the process's exe or any ancestor's exe matches `always_direct` → `Direct` / `AlwaysDirectApp`.
4. **Own pass.** For groups in order, a rule matches when all of its non-empty conditions hold for the process itself. Domain conditions need `f.domain`.
   - If `f.domain` is `None`, the flow is TCP on port 80 or 443, and an earlier-ordered rule would match except that the domain is unknown → `NeedDomain`.
   - Otherwise, the first match → `Own`.
   - A rule with no `apps` counts as an Own match for any process.
5. **Inherited pass.** Only when the Own pass found nothing other than the catch-all. Walk `ancestors(pid)`, nearest first. The first ancestor matching a rule that has non-empty `apps` and `include_children = true` → `Inherited { from_pid }`.
6. Otherwise, the catch-all group → `CatchAll`. If there is no catch-all → `Direct` / `NoMatch`.
7. `Action::Proxy(id)` maps to `Route::Proxy(id)`. During M1, if `proto` is UDP or `dst` is IPv6 and the route is `Proxy` → `Block`, with the same MatchInfo.

- [ ] **Step 1: Write failing tests.** All use the seed config with Steam enabled, plus a group "Filtered game" (app `fgame.exe`, Proxy `v2ray`) placed **after** Steam.

### Task 12: Transparent relay (service)

**Files:**
- Create: `crates/q2route-service/src/relay.rs`, `src/stats.rs`
- Test: `crates/q2route-service/tests/relay.rs`

**Interfaces:**
- Consumes: `decide` (Task 6), `peek_host` (Task 7), `connect_via` (Task 8), `NatTable` (Task 11).
- Produces:
  ```rust
  pub trait OrigDstLookup: Send+Sync { fn lookup(&self, peer:SocketAddr) -> Option<OriginalDst>; }
  pub struct RelayCtx { pub rules: ArcSwap<RuleSet>, pub cfg: ArcSwap<Config>, pub tree: Arc<RwLock<ProcessTree>>, pub excluded: ArcSwap<HashSet<u32>>, pub stats: Arc<Stats>, pub own_ports: Arc<DashSet<u16>> /* local ports of relay's direct upstreams; capture skips them */, pub events: broadcast::Sender<Event>, #[cfg(test)]/#[doc(hidden)] pub bypass_lan_rule_for_tests: bool }
  pub async fn run_relay(listener:TcpListener, lookup:Arc<dyn OrigDstLookup>, ctx:Arc<RelayCtx>, cancel:CancellationToken) -> io::Result<()>
  pub struct Stats; impl Stats { pub fn add(&self, group:&str, up:u64, down:u64); pub fn snapshot(&self) -> (HashMap<GroupId,GroupStats>, u64, u64) /* bps over last 1s */ }
  ```

**Per accepted connection:**
1. Look up the original destination.
2. If `decide` returns `NeedDomain`, read up to 4 KiB until `peek_host` returns `Host` or `NotFound`, or `peek_timeout_ms` passes. Then decide again with the domain.
3. Then:
   - `Proxy(id)` → `connect_via` with a `Domain` target when the domain is known, otherwise an `Ip` target, and a 5 s timeout.
   - `Direct` → `TcpStream::connect(dst)`, recording its local port in `own_ports`.
   - `Block` → close.
4. Write the peeked bytes upstream first, then copy in both directions, counting bytes into `stats`.
5. **If the proxy fails, close the client connection and emit `Event::ProxyDown`. Never fall back to direct.**

    - `console`: run in the foreground for debugging
  - **`Engine::start` does the following:**
    - Load the config.
    - Compile the rule set.
    - Snapshot the processes into the tree and keep it updated, polling `list_processes` every 1 s (ETW is a later improvement).
