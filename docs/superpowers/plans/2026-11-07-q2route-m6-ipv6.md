# Q2Route M6: IPv6 through the proxy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** IPv6 TCP and UDP from apps routed to a proxy go through the proxy (instead of being blocked), with the same fail-closed guarantees as IPv4; IPv6 TCP/53 is routed by name like IPv4 (closing the M4 gap).

**Architecture:** Generalise the IPv4-only pieces to both families: the NAT reflection table and packet rewriter handle IPv6 headers; the relay listens on IPv4 *and* IPv6 on the same port; the classifier redirects non-Direct IPv6 TCP and hands proxied IPv6 UDP to the UDP relay; the UDP relay keys sessions by `SocketAddr` and injects IPv6 replies; the ICMP guard also covers ICMPv6. Proxies are reached as today (usually over IPv4 loopback); the IPv6 *destination* is sent to the proxy as a SOCKS5 ATYP-4 / bracketed HTTP CONNECT target, never resolved or connected locally.

**Tech Stack:** Rust, tokio, WinDivert (existing), etherparse (dev-dep for tests).

**Spec:** `docs/specs/2026-11-05-q2route-design.md` — §2 goal 1 (IPv4 and IPv6), §3 "No IPv6 bypass. IPv6 from proxied apps or destinations is proxied or blocked, never sent direct."

## Global Constraints

- **Fail closed:** any IPv6 packet the code can't handle safely (unsupported extension headers before TCP/UDP, fragments, a NAT rewrite that fails, a SOCKS4 profile for an IPv6 target, a relay listener that couldn't bind IPv6) is dropped / the connection closed — never passed.
- IPv4 behaviour is unchanged (all existing tests keep their meaning).
- Proxied UDP to port 443 (QUIC) stays Block for both families (M3 decision).
- The NAT table and the relay's own-port set must not confuse an IPv4 and an IPv6 socket that use the same port number.
- `cargo clippy --workspace --all-targets` clean, `cargo fmt --all`, all tests pass; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisions made in this plan (builder's calls)

- **NAT key:** `(Family, port)` where `Family` is `V4 | V6`; `OriginalDst.dst: SocketAddr`.
- **Relay port:** bind the IPv4 listener on `0.0.0.0:0`, then the IPv6 listener on `[::]:<same port>` with `IPV6_V6ONLY`; if the IPv6 bind fails, retry the pair (up to 10 attempts), and if IPv6 can't be bound at all, start anyway with IPv4 only and keep proxied IPv6 TCP **blocked** (logged once at warn).
- **Extension headers:** the NAT rewriter handles IPv6 packets whose TCP header follows the fixed 40-byte header directly (next header 6); anything else on a redirected flow is dropped (Windows rarely adds extension headers to TCP).
- **DNS over IPv6:** IPv6 TCP/53 is redirected into the relay exactly like IPv4; with that in place the M4 special cases for IPv6 apps are removed: the DnsProxy answers TC=1 (not REFUSED) to IPv6 apps when no association exists, and a TC=1 answer from the resolver is passed through verbatim to IPv6 apps too.
- **ICMPv6 guard:** outbound `icmpv6.Type == 1` (destination unreachable) quoting UDP to a port the UDP relay serves (or served within `ICMP_GUARD`) is dropped, mirroring the ICMPv4 guard.

## Review Focus

1. An IPv4 socket and an IPv6 socket on the same local port, one Direct and one proxied: neither gets the other's NAT entry or own-port exemption. Test: `same_port_v4_v6_do_not_collide` (Task 1, and own-ports in Task 2).
2. An IPv6 TCP packet with a hop-by-hop or routing header on a proxied flow: dropped, never passed or mis-rewritten. Test: `ipv6_extension_header_on_redirected_flow_dropped` (Task 1).
3. The machine has no IPv6 at all (relay can't bind `[::]`): the service still starts; proxied IPv6 stays blocked; IPv4 works. Test: `relay_starts_ipv4_only_when_ipv6_bind_fails` (Task 2).
4. A SOCKS4 profile asked to reach an IPv6 destination: the connection is closed, nothing direct. Test: `socks4_ipv6_target_closes` (Task 2).
5. A proxied app's IPv6 DNS over TCP: routed by name through the relay (no longer always-Direct). Test: `ipv6_tcp_dns_routed_by_name` (Task 4).

### Task 2: Dual-stack relay, IPv6 TCP routing, IPv6 proxy targets

**Files:** Modify `crates/q2route-service/src/relay.rs`, `packet_loop.rs`, `classify.rs`, `engine.rs`, `crates/q2route-core/src/decide.rs` (`finalize`), `crates/q2route-core/src/proxy.rs` (only if the HTTP CONNECT target isn't bracketed for IPv6 today); tests in `tests/relay.rs`, `classify.rs`, core `tests/decide.rs`, `tests/proxy.rs`.

**Interfaces / behaviour:**
- Core `finalize`: `Action::Proxy` → `Route::Proxy(id)` for IPv6 TCP and IPv6 UDP (port ≠ 443); UDP/443 stays Block for both families. Update the tests that pinned IPv6 → Block.
- `proxy.rs`: `Target::Ip(SocketAddr::V6)` → SOCKS5 ATYP 4; HTTP CONNECT `[addr]:port` with `Host: [addr]:port`; SOCKS4 → `Err(Protocol("SOCKS4 cannot reach IPv6"))` (already) → the relay closes the client.
- Relay: `run_relay` accepts on two listeners (IPv4 + IPv6, same port, per Decisions); `RunState`/engine record whether IPv6 is available (`relay_v6: bool`). Peer → original destination lookup by `(Family::of(peer), peer.port())`. `connect_direct(ctx, dst: SocketAddr)` binds `0.0.0.0:0` or `[::]:0` by family. `own_ports` becomes a set of `(Family, u16)`.
- `classify`: a non-Direct IPv6 TCP SYN → `NewRedirect { pid }` when `relay_v6` is true, else `Drop` (pass `relay_v6` in; keep the existing fail-closed rules for non-SYN packets). `route_packet`: the relay-port / own-port / nat_has checks work for both families (`tcp4` → `tcp`).
- Engine: binds the listener pair, passes `relay_v6`, logs `relay listening on <port> (IPv4[+IPv6])`.
